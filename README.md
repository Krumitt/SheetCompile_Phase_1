# SheetCompile — Phase 1

**A Spreadsheet-to-Code Compiler for Translating Excel Formula Logic into
Scalable Python and SQL Implementations**

Phase 1 = Front End and Correctness Baseline. This phase implements the full
compiler front end for a documented subset of Excel formula syntax:
extraction → lexing → parsing → AST → symbol table → dependency graph →
reference evaluation, validated by an automated test suite against sample
workbooks.

## Project structure

```
sheetcompile/
├── language_spec.py     # token types + EBNF grammar (read this first)
├── extractor.py          # reads .xlsx via openpyxl -> raw formulas/values
├── lexer.py               # formula string -> token stream
├── ast_nodes.py           # AST node classes + pretty_print()
├── parser.py              # token stream -> AST (recursive descent)
├── symbol_table.py        # tracks cell refs, named ranges, cross-sheet refs
├── dependency_graph.py    # cycle detection + topological evaluation order
├── evaluator.py           # walks the AST, computes the cell's value
├── error_reporter.py      # shared diagnostic format + exception hierarchy
├── main.py                # wires the whole pipeline together, CLI entry point
├── requirements.txt
└── tests/
    ├── create_test_workbooks.py   # generates the 3 sample workbooks
    ├── expected_values.py         # hand-computed correctness baseline
    ├── test_pipeline.py           # runs the full pipeline, pass/fail report
    └── workbooks/                 # pricing.xlsx, payroll.xlsx, inventory.xlsx
```

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

## Run the test suite

```bash
python tests/create_test_workbooks.py   # generates the 3 sample .xlsx files
python tests/test_pipeline.py           # runs the full pipeline, prints pass/fail
```

Expected: `16/16 checks passed`.

## Run the CLI on any workbook

```bash
python main.py tests/workbooks/pricing.xlsx
```

Prints every cell's evaluated value as `Sheet!Cell = value`.

## Compiler-design concept map (for Review 1 / viva)

| Course concept | Module | What it demonstrates |
|---|---|---|
| Lexical analysis | `lexer.py` | Hand-written scanning-loop tokenizer; reports illegal characters, malformed numbers, unterminated strings with position |
| Language specification | `language_spec.py` | Formal token list + EBNF grammar with documented operator precedence |
| Syntax analysis / parsing | `parser.py` | Hand-written recursive-descent parser, one method per grammar rule |
| Abstract Syntax Tree | `ast_nodes.py` | Typed AST node classes + `pretty_print()` visualization |
| Symbol table management | `symbol_table.py` | Tracks cell refs, named ranges, cross-sheet refs |
| Dependency / data-flow analysis | `dependency_graph.py` | DFS-based 3-colour cycle detection + topological sort |
| Semantic analysis / interpretation | `evaluator.py` | Tree-walking evaluator implementing the semantics of every supported function; raises `SemanticError` for type errors |
| Error detection and reporting | `error_reporter.py` | Unified diagnostic format: `Error at Sheet!Cell, position N: message` |

## Known Phase 1 limitations (documented honestly, on purpose)

- **Cycle detection is workbook-wide, not per-component.** If *any* cell in
  the workbook has a circular reference, `main.py` currently reports the
  error and does not evaluate the rest of the workbook, even cells unrelated
  to the cycle. Real Excel would still compute the unrelated cells. This is
  a deliberate Phase 1 simplification — worth mentioning proactively in
  the viva as a Phase 2/3 improvement, not a bug you're unaware of.
- **No Excel-cached values in the generated test workbooks.** `pricing.xlsx`,
  `payroll.xlsx`, and `inventory.xlsx` are generated by `openpyxl`, which
  does not evaluate formulas — so they carry no Excel-computed cached
  values. `tests/expected_values.py` supplies a hand-computed correctness
  baseline instead. `extractor.py` *does* already read cached values
  (`ExtractedCell.cached_value`) for workbooks that were actually opened
  and saved by real Excel/LibreOffice — that path is ready for Phase 2/3
  once real-world workbooks are used.
- **`inventory.xlsx` intentionally contains both bugs at once**: a circular
  reference (`D1`/`D2`) and a type error (`E2 = SUM(E1)` where `E1` is
  text). Because the circular reference blocks whole-workbook evaluation
  (see above), the type-error path is unit-tested directly against
  `evaluator.py` rather than through the full pipeline on this file —
  see `test_type_error_detected()` in `tests/test_pipeline.py`.

## Scope boundary (per project proposal, Section 5)

Phase 1 stops at the reference evaluator and correctness baseline.
Phase 2 (Python/pandas code generation) and Phase 3 (SQL code generation,
backend-selection heuristic, benchmarking) are **not** implemented here —
that is the defined Phase 1/Phase 2/Phase 3 boundary from the project
proposal, and this repository intentionally does not cross it yet.
